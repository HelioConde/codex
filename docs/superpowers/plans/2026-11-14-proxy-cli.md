# Integracao local do Codex com VideoForge

**Data:** 14/11/2026. **Fonte:** pedido de implementacao e escolha explicita do usuario por mesclar provider e perfis globais.

## Design e escolhas

Reutilizar ProxyClient e o Docker existente. Mesclar somente novas tabelas de provider/perfis em ~/.codex/config.toml, com backup privado dos bytes originais e recusa de colisao. Preservar as opcoes existentes. Um comando local seleciona o perfil economico e injeta a chave apenas no ambiente do processo filho. O Codex original continua acessivel sem esse comando.

Alternativas consideradas: lancador sem instalar configuracao (reversivel, mas nao entrega os perfis globais escolhidos); substituir configuracao global (descartada, perderia preferencias); mesclar provider e perfis (escolhida pelo usuario).

Luna/low para simple, Sol/medium para code, Sol/high para complex, Astra/high para critical. Classificacao explicita e deterministica evita gastar uma chamada somente para escolher modelo. Nao criar agentes automaticamente. Catalogo /v1/models valida disponibilidade; nao pressupor que seu formato seja o catalogo nativo Codex.

Usar Responses/SSE nativo da CLI, WebSocket desativado e retries zero. Preflight sem inferencia verifica health/modelos. Fallback para configuracao original somente antes de iniciar a sessao, mediante flag; nunca repetir uma tarefa apos erro de inferencia. Execucao gerativa exige --execute. Configuracao nao altera a IA desta conversa.

Preservar cliente de imagens, workflows manuais e pipeline VideoForge. Credenciais somente em memoria/ambiente. Sem chamadas gerativas no CI. Metricas locais sem prompts e sem equivalencia inventada entre tokens API e creditos.
